# M1.5 plan — Second model provider

Spec reference: `agent-runtime-spec.md` §3 (model API row), §14 M1.5.

## Status: implemented (2026-09-08)

Everything below is done and green under `make test`. What changed from the spec's sketch
while building:

- **Routing lives in the model string, not a worker flag.** The spec offered two demos: run
  the same goal against both providers, or a per-run `agent_config.model` override that picks
  the provider. Both fall out of one mechanism: a `model.Router` that resolves the backend from
  the model name (`anthropic/…`, `local/…`, bare `claude-*`). ADR-10.
- **Two additive changes to shared types were needed.** `ContentBlock` gained `thinking` /
  `redacted_thinking` block types (ADR-11) and `Usage` gained cache token counts, because both
  are things the event log must carry for a hosted, reasoning model and neither existed for a
  local one. `Response` gained a `Provider` tag so the router can name the real backend. The
  loop changed by one statement (read that tag); the reducer and the event schema did not
  change.
- **Unpriced models are refused** rather than priced at zero, and refusals are errors. ADR-12.

Not verified live from this machine: `make test-live-anthropic` and `make compare` need an
`ANTHROPIC_API_KEY`, which was not available when this was built. The unit tests drive the real
SDK client against an `httptest` server and assert the exact wire body, so what is untested is
the API's acceptance of that body, not the translation. Run the live test once before relying on
the provider.

## Goal

Add an Anthropic `ModelProvider` behind the M1 interface with no changes to the loop, the reduce
function, or the event schema, and use its real per-token cost to exercise the budget path end
to end. Exit criteria:

1. A run with `agent_config.model = "anthropic/claude-opus-5"` completes through the same
   worker that serves local runs, with `model_responded.provider = "anthropic"` and a nonzero
   `spent_usd`.
2. A run against Claude with a small budget terminates `budget_exceeded`.
3. Unit tests assert the exact Messages API request body and the translation back; an
   integration test runs two backends behind the router.
4. README paragraph, ADRs, this plan.

## Design

```
internal/model/
  provider.go          + BlockThinking, BlockRedactedThinking; ContentBlock.{Thinking,Signature,Data}
                       + Usage.{CacheReadInputTokens,CacheCreationInputTokens}; Response.Provider
  pricing.go           + Price.{CacheReadPerMTok,CacheWritePerMTok}
  router.go            Router: Register(name, provider, match), Resolve, Complete, CostMicroUSD
  anthropic/
    anthropic.go       SDK client; toParams / fromMessage; RefusalError; debug middleware
    pricing.go         DefaultPrices (snapshot 2026-09-08), longest-prefix lookup, ParsePrices
    anthropic_test.go  httptest-backed: wire body, stop reasons, refusal, errors, pricing
    live_test.go       opt-in: tool call, then echo the thinking turn with a tool result
internal/runtime/loop.go   provider name from Response.Provider (one statement)
cmd/agentd/main.go         buildProvider: local + anthropic behind a Router;
                           -anthropic-prices, -anthropic-thinking-display
scripts/compare-providers.sh
```

Translation notes:

- `system` becomes one text block; `max_tokens` defaults to 16000 when the run sets none
  (thinking output counts against it).
- Tool schemas from the registry are passed through with every keyword: the SDK's typed schema
  only knows `properties` and `required`, so the rest (`additionalProperties`, patterns, bounds)
  travels in `ExtraFields`. The unit test asserts the wire schema equals the registry schema.
- `temperature` is forwarded only when set. The loop never sets it, which is right for current
  models (they reject non-default sampling parameters).
- No `thinking` parameter is sent unless `-anthropic-thinking-display` is set; current models
  reason by default with the text omitted. Setting `summarized` records readable reasoning.
- Stop reasons map onto the three the loop knows (`end_turn`, `tool_use`, `max_tokens`);
  `refusal` is an error; anything unrecognised is stored as-is. The loop decides on tool_use
  blocks, not the stop reason, so an unknown value cannot derail a run.
- Cost is `input·in + output·out + cache_read·read + cache_write·write` in micro-USD from the
  price table. Nothing here requests prompt caching yet; the fields are there so the accounting
  is right when M4 turns it on for the stable prefix (tools + system prompt).

## Explicitly not in M1.5

Prompt caching (M4, with the metrics to see it work), streaming (nothing consumes partial
output yet), server-side refusal fallbacks (a durable runtime should record the refusal, not
silently switch models mid-run; revisit if refusals turn out to be common), Bedrock / Vertex
clients (same SDK, different constructor; add when there is a deployment that needs one).
